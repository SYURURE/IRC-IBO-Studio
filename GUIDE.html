利用前に確認する注意事項

WindowsのSmart App ControlによるIboViewの起動ブロック

Windows 11のSmart App Control（スマートアプリコントロール）が有効な環境では、IboViewの起動がブロックされ、StudioからIBOの計算・軌道表示・PNG保存まで進めない場合があります。 オンであれば必ずブロックされる、という意味ではありません。配布ファイルやWindows側の判定によって異なります。

利用者の環境では、「構造をコピー ＋ 起動」を押した際に、次のエラーが報告されています。

[WinError 4551] アプリケーション制御ポリシーによってこのファイルがブロックされました。

これはWindows側で実行を拒否されたことを示します。エラー番号だけではSmart App Controlが原因とは断定できないため、Windowsの通知と保護設定も確認してください。

- 影響範囲： IboViewを起動できない間は、IboView内の電子状態・IBO計算、軌道描画、新規のPNG連番生成を行えません。Studioが起動できれば、IRC/XYZの読み込み・経路整理・XYZ保存は利用できます。既存PNGからの動画化も、必要な動画出力環境が動作すれば利用できます。

- 確認方法： 配布フォルダーを全て展開したうえで、Studioで指定したIboView.exeを直接ダブルクリックし、単体で起動するか確認します。Windows セキュリティ → アプリとブラウザー コントロール → スマートアプリコントロールの設定で状態を確認できます。単体でもブロックされる場合、Studioの再セットアップではWindows側の制限を解除できません。

- 単体では起動できる場合： Studioの実行ファイル指定がそのIboView.exeと同じか確認します。既に正常起動しているIboViewには「構造のコピーのみ」→ IboView上でCtrl＋Shift＋Vで受け渡せます。この操作は起動ブロックを解除するものではありません。

- 保護設定について： Microsoftの案内では、Smart App Controlには特定アプリだけを許可する例外設定がありません。オフにするとIboView以外に対する同機能の保護も外れます。本ソフトの必須手順として無効化を求めるものではなく、自動で設定を変更することもありません。管理端末では管理者に相談してください。再度オンにできる条件はWindowsの更新状況などに依存するため、変更前に公式資料と画面の注意書きを確認してください。

- 署名付き版について： 2026年10月4日の調査時点では、IboViewの署名付きWindows版の配布先は確認できていません。署名付き版への交換で解決できるとは保証しません。必要に応じてIboView配布元へ確認してください。

参考：Microsoft：Smart App Control FAQ、IboView公式ダウンロード。記載内容の確認日：2026年10月4日。

計算・表示・保存時の注意

- メモリと計算負荷： IboViewのRequired Memoryに加えて、Windowsや他アプリ用の余裕が必要です。計算画面の注意書きを確認し、まず少数の構造で試してください。全フレームの軌道描画（Ctrl＋T）でも追加のメモリを使用します。スレッド数を増やしても必ず速くなるとは限らず、作業領域が増える場合があります。基底を小さくする場合は計算条件の変更として記録してください。

- 計算条件の引き継ぎ： XYZへの書き出しで元の波動関数は渡りません。電荷・スピン・汎関数・基底はIboView側で確認してください。元のIRCと異なる条件で計算すれば、異なる条件での軌道解析になります。収束失敗した点を含めたまま解析を進めないでください。

- 解析結果の解釈： 経路の点数・原子順序・始点/終点・TSを確認してください。動画は実時間の分子運動ではありません。軌道の色や形、反応軌道の候補順位だけで反応機構を断定しないでください。人工サンプルは操作確認用で、計算済みIRCや実験データではありません。

- 保存とバックアップ： 元ログは保管し、研究ごとに空のPNG出力フォルダーを用意してください。同じ保存スクリプトの再実行では同名PNGを上書きする可能性があります。StudioのプロジェクトJSONにはIboViewの波動関数・軌道・表示状態は含まれないため、必要なIboView側のデータも別途保存してください。

- クリップボードとスクリプト： IboViewのCtrl＋Shift＋Vはクリップボードのスクリプトも実行します。構造の貼り付けとPNG保存スクリプトの実行を区別し、内容・出所を確認できないスクリプトを実行しないでください。

- MP4出力： MP4にはFFmpegが必要です。FFmpeg自体がWindowsの保護機能でブロックされる場合もあり、IboViewが起動できることとは別に確認が必要です。MP4出力が利用できなければ、PNGを保持し、GIF出力を試してください。

- 不具合報告と研究データ： 使用バージョン、Windows/Pythonのバージョン、操作手順、エラー全文を添えると切り分けやすくなります。公開Issueにログや画像を添付する前に、未公開の分子構造、ユーザー名、所属、ファイルパスなどを確認し、共有可能な最小サンプルに置き換えてください。

ダウンロードから起動まで

前提：Windowsに64-bit Python 3.10以上（Tcl/Tk・pip・venvを含む）があり、.pyw がPythonに関連付けられていること。初回のみネット接続が必要です。このZIPはPython本体やIboViewを同梱していません。

1. ZIPを置きたいディレクトリにダウンロードします。

2. ZIPを右クリックして「すべて展開」。書き込み可能な場所に展開し、ファイルを個別に取り出さないでください。

3. 展開フォルダーの 01_setup.pyw をダブルクリックします。Python仮想環境を構築し、必要なモジュールをインストールします。一覧に各モジュールの状態を表示します。失敗した場合は画面の案内とsetup.logを確認し「再試行」。

4. 完了後は 02_start.pyw をダブルクリックして起動します。通常起動時にpipや再インストールは実行しません。

初回用を再実行すると新しい仮想環境を構築し、起動確認に成功した時点で使用する環境を切り替えます。以前に完成した環境は保持します。フォルダーを移動した場合も01_setup.pywを再実行してください。以前のバージョンに上書きせず、新しいフォルダーへ展開してください。

セットアップの工程とキャンセル

- 工程1：Python仮想環境の構築。 本ソフト専用の仮想環境を作り、モジュール導入用のpipも準備します。

- 工程2：Pythonモジュールのインストール。 requirements.txtから、numpy（座標・数値計算）、Pillow（画像処理）、imageio-ffmpeg（動画作成用FFmpeg）をあらかじめ一覧表示します。状態は「未インストール → インストール中 → インストール終了」と変わります。追加の依存モジュールも同じ仮想環境に導入します。

- 工程3：起動確認。 必要なモジュールとTk画面の起動を確認します。成功すると進捗バーが100％になり、「Studioを起動」が使えます。

- 実行中にキャンセルまたはウィンドウの×を押すと、インストーラーとその子プロセスを一時停止し、確認ウィンドウを開きます。

- 確認のOKで中止。プロセス終了後、今回新しく作った仮想環境を削除するため、そこに導入したモジュールと依存モジュールも削除されます。後始末中は完了まで待ってください。既存のPython・以前に完成した環境・入力データは保持します。削除に失敗した場合は成功扱いにせず、残った場所をエラー表示します。

- 確認のCancelで同じ処理を再開。長時間停止したために通信がタイムアウトした場合は、エラー内容を確認して再試行してください。

- 中止後の「再試行」は仮想環境の構築からやり直します。電源断やタスクマネージャーによる強制終了は、確認付きキャンセルとは異なり、後始末まで完了できない場合があります。

PythonやIboViewがまだない場合

- Python公式 https://www.python.org/downloads/ からWindows用Pythonを導入します。Python install managerを使用する場合は新しいPowerShellで py install 3.13 を実行。py -3.13 -m tkinter で小窓が開くことを確認して閉じます。

- .pywを開くとエディターやアプリ選択が出る場合は、右クリックの「プログラムから開く」でPython Launcher / Pythonを選び、既定に設定してください。Python自体がない場合は先に導入が必要です。関連付けはPCの設定に依存します。

- IboView公式 https://www.iboview.org/ からWindows版を取得し、配布フォルダー全体を展開してiboview.exeを起動確認します。

- Windowsのセキュリティ設定・実行ポリシー・除外設定は変更しません。BATは同梱しません。ただし、PCの保護設定による実行可否までは保証できません。再びブロックされた場合は警告内容を確認してください。

操作一覧は同梱 IRC_IBO_Studio_Workflow_A4.pdf（表記はv0.3.1ですが、起動・操作手順はv0.3.7でも共通です）、詳細はアプリ内の「使い方」（GUIDE.html）です。

1 経路

- 「IRC / XYZを開く」でGaussian IRCログ（.log / .out）または複数構造XYZを読み込みます。「人工サンプルを開く」では、数式で新規作成した71構造の操作用サンプルを読み込みます。実際のIRC計算結果ではありません。

- Forward / Reverseが別ファイルなら「Forward ＋ Reverseを統合」。同じTS・原子順序・計算条件を確認し、TSを一つにして経路を並べます。Forwardが生成物側とは限らないので両端を確認してください。

- 左の一覧・スライダー・エネルギー図から点を選択できます。開始／終了は一覧の位置番号（0開始）。間隔を指定して間引いても、選択区間の両端と統合したTSは含めます。

- 「重原子で向きをそろえる」は全点を最初の構造に剛体整列します。原子順序や内部距離は変えません。IboViewで計算する前に設定してください。

- 構造プレビュー：左ドラッグで回転、Shift＋左ドラッグで並進、ホイールで拡大縮小。原子を2つクリックすると距離、Escで解除。「原子番号・元素」「結合」の表示切替とPNG保存ができます。

- 構造プレビューはGRRMインプットビルダーに合わせた白背景・球棒表示です。IBOの電子密度面はIboView側で表示します。

- 「選択範囲をXYZへ保存」で外部ファイルに書き出せます。プロジェクトJSONには全経路と選択範囲・表示設定・計算条件メモを保存します。IboViewの計算結果は含みません。

2 IboView

この欄を見ながら、別ウィンドウのIboViewを操作してください。Ctrlキーの操作はIboViewをクリックしてから行います。下の続きはスクロールできます。

1 経路を貼り付ける

【Studio】「① 構造を渡す」の「構造をコピー ＋ 起動」を押します。IboViewが起動済みなら「構造のコピーのみ」。

【IboView】ウィンドウをクリックして Ctrl＋Shift＋V。分子モデルが表示されます。このショートカットは Edit → Exec Script（Clipboard）からも使えます。

確認：Data Sets → Framesを開き、Current Frameのつまみ／番号欄を変えて構造が切り替わるか確認します。この段階では球棒モデルだけで正常です。軌道は次の計算後に表示します。

別の経路がすでに開いている場合は、必要な作業を保存してから File → Closeで閉じ、新しい経路を貼り付けます。

2 計算画面を開き、条件を確認する

【IboView】Ctrl＋Enter、または「Compute Wave Function」を押します。

上部の「Run Hartree-Fock/Kohn-Sham (DFT)」と「Run Chemical Analysis (IAO/IBO)」を両方オンにします。今回はXYZから電子状態とIBOを計算するため、両方が必要です。

「Wave Function」タブで次を確認します。

・Charge：分子全体の電荷。

・Extra Spin：スピンの指定。多重度をそのまま入力する欄ではありません。通常の偶数電子・閉殻一重項なら0ですが、対象の電子状態を確認してください。

・SCF Method / Functional / Orb. Basis：計算方法・汎関数・軌道基底。研究目的に合う条件を選びます。

「① 構造を渡す」の元データ情報も参考にしてください。XYZには電荷・スピン・波動関数が引き継がれません。Studioの「計算条件のメモ」は記録用で、ここには自動反映されません。

3 IBO解析を指定し、計算する

【IboView】同じダイアログの「Chemical Analysis」タブを開き、「Orbital Localization」がIBOになっていることを確認します（例：IBO (exponent 2)）。

「Wave Function」に戻り、Number of ThreadsとRequired Memoryを確認。必要メモリを確保できる条件で「OK」を押し、読み込んだ経路の計算完了を待ちます。

計算が正常に終わったら計算ログの「Close」を押します。エラーや収束失敗が出た場合はそこで止め、ログ内容を確認してください。

メモリ不足時は他のアプリを閉じるなどで空きを確保します。基底の縮小は計算条件の変更です。点数を減らしても1点あたりの必要メモリは減らない場合があります。

4 反応に関わる軌道を表示する

【IboView】上部メニューの View → Find Actively Reacting Orbitals… を開きます。経路に沿って変化する軌道の候補が表に出ます。

見たい軌道の行をダブルクリックすると、分子の周りに軌道の面が表示されます。必要な軌道ごとに繰り返します。同じ行のダブルクリックで表示／非表示を切り替えられます。

別の探し方：Data Sets → Framesの「Track Orbital」で軌道番号を選び、「Show #…」を押して表示します。Data Setsの軌道一覧でもダブルクリックで表示できます。

まず1つ表示して形を確かめ、必要な軌道を追加すると見やすくなります。候補の順位だけで反応機構を断定せず、構造と軌道の変化を確認してください。

5 色と視点を整える

【IboView】表示中の軌道をData Setsの一覧、または3D画面で1回クリックして選択。「Render: Orbital」（版によりOrbitals表記）の設定で色や面の表示を調整します。

IboViewの3D画面では次のマウス操作を使います。

・回転：右ボタンを押したままドラッグ。

・並進移動：左右のボタンを両方押したままドラッグ。

・拡大縮小：右ボタンを押したままホイール。

Studioの構造プレビューとは操作が異なります。動画用には分子全体が収まる視点に整えます。

6 全点の軌道を描画し、変化を確認する

【IboView】表示する軌道を選び終えたら Ctrl＋T。選んだ軌道の面を全フレームで作るので、描画が終わるまで待ちます。

Data Sets → Framesの「Current Frame」を動かして、始点から終点まで確認します。キーボードなら3D画面の空白をクリックしてから Shift＋←／→で前後の点へ移動できます。

確認：目的の軌道が経路に沿って表示され、分子が画面外に切れていないかを見ます。Ctrl＋Tは動画保存ではなく、全点の軌道面を準備する操作です。

7 PNG連番を保存して動画へ進む

【Studio】「③ PNGを保存」で空のPNG保存フォルダーを指定し、「PNG保存スクリプトをコピー」。

【IboView】いまIBOを表示しているウィンドウをクリックして Ctrl＋Shift＋V。今度は構造の貼り付けではなく、コピーした保存スクリプトが実行されます。全フレームのPNG保存が終わるまで待ち、保存先に画像ができたことを確認します。

【Studio】「3 動画」へ移動し、「このフォルダーを読み込む」。プレビューで確認後、FPS・MP4／GIF・往復再生を指定して「動画を書き出す」。

表示名はIboViewのバージョンによって多少異なります。

3 動画

- PNG保存フォルダーは「2 IboView」と共通です。「このフォルダーを読み込む」または「PNG連番を読み込む」で画像を読み込みます。

- PNGはファイル名の数字順で並べます。すべて同じ画像サイズ・視点で保存してください。別の画像を混ぜないでください。

- 右の画像・スライダー・プレビューボタンで確認し、FPS（1～60）、MP4またはGIF、往復再生の有無を選んで「動画を書き出す」。既存の同名動画には上書きしません。

- FFmpegは通常空欄で自動検出します。依存パッケージに含まれる実行ファイルを利用できます。利用できない環境では手動指定するかGIFを選んでください。

- IRC経路は時間軸ではありません。動画のFPSは表示上の速度です。

- 残りを3タブに再番号付け。経路画面の操作階層・余白、IboView画面の幅に応じた2列／1列配置、動画画面のフォルダーと設定・プレビュー配置を整理しました。狭い画面ではボタン折返しとフォームの縦スクロールを使えます。

- 旧プロジェクトは引き続き読み込めます。削除機能の設定は無視し、元ログの電荷・多重度などの科学データは保持します。Gaussian IRCログの読み込みは残しています。

起動しない・読めない場合

- py が見つからない：Python install managerを導入し、PowerShellを開き直して上のコマンドを実行してください。

- Tcl/Tkがない／32-bit Python：64-bit版とTcl/Tkを導入し、01_setup.pywを再実行します（入力データは移動不要）。

- 初回インストール失敗：ネット接続とエラー末尾を確認し、01_setup.pywを再実行。会社などの管理端末ではソフト導入条件を確認してください。

- IboViewが起動しない：IboView配布フォルダーを丸ごと展開したか、exeを単独で移動していないか、指定パスが正しいか確認します。

- 読込エラー：「読み込み情報・注意点」と元ログを確認してください。GaussViewで開けても、対応していないログ形式ではStudioで読めない場合があります。

- Gaussianログは完了点とその直前の電子エネルギー評価を対応付けます。RCFCの開始点0では、ログに印字されたCHK由来Cartesian座標とEnergy From Chkを採用できる場合があります。未来の点の座標・エネルギーで補完しません。途中打切りや注意点も表示します。

- 原子順序は一貫している必要があります。結合線は原子間距離からの表示用推定です。エネルギー図はSCF値の先頭構造基準であり、自由エネルギー障壁ではありません。

検証と制限

python -m unittest discover -s tests -v でテストできます。詳細はVALIDATION.mdを参照してください。Windowsの実画面・IboView内の計算と描画はこの更新作業環境では実機検証していません。

PythonとIboView、各依存ライブラリはそれぞれの提供元の製品です。本アプリはIboView作者またはGaussian社の公式製品ではありません。
